# R1.2 障害注入マトリクス

試験は`RUN_TESTS.bat`でWindowsの一時ディレクトリ内にテスト用乱数データを生成して行います。実データは操作しません。

| 擬似強制停止地点 | 事前の副作用 | 通常の安全復旧 | 手動確認 |
|---|---|---|---|
| `journal-recorded` | 記録とストアリンクを作成 | 元パスのSHAを確認して記録を解消 | 原則不要 |
| `backup-renamed` | 重複元を退避名に移動 | 退避ファイルのSHAを確認して元パスに復元 | 検証が失敗すれば必要 |
| `new-link-created` | 元パスに代表データへのリンク、退避も残る | **双方に触れない** | **必要** |
| `pre-backup-delete` | 両パスが残る | **双方に触れない** | **必要** |
| `backup-deleted` | 退避は削除され、元パスはリンク済み | 元パスのSHAを確認して記録を解消 | 異常があれば必要 |

- **通常I/O例外**も`journal-recorded`, `backup-renamed`, `new-link-created`, `pre-backup-delete`で別途注入。適用中に例外が発生した場合、元の独立ファイルを維持するロールバック処理を検証する。
- `CHAPPY_TESTING`のコンパイル定義はテストプロジェクトだけに設定。通常のGUIビルドで注入フックは動作しない。
- この方式は**例外の模擬**であって、突然の電源断、ファイルシステム破損、第三者プロセスからの競合操作を完全に再現しない。
- 退避ファイルを持つ未解決操作がある場合、**次の統合をブロック**する。
