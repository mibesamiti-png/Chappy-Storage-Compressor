# R2 完全無劣化のPNG/JPEG最適化設計（まだ未実装）

## 透明性・互換性

R1.4で `PngInspector.Inspect(path)` を追加。R1.5では `PngLosslessOptimizer.CreatePreview` を追加し、IDATのzlib再圧縮・展開後のフィルタ済み画像データ完全一致・非IDATチャンクの完全一致・候補縮小判定を実装した。**元画像の置換や削除は行わない**。C#実行テストとWindowsビルドは未実施。

R2では「ピクセル内容が同一」と「ファイルを1バイトも変更しない」を明確に分ける。ユーザーが指定した『完全無劣化』は、少なくとも色/透明度を含めて**デコード後の画素が完全一致**し、EXIF/ICC/XMP/動画音声トラックなどの付加情報も保護すること。再圧縮後のファイルバイト列まで一致するわけではない。必要なら原本を別ドライブへ保存する。

## PNGの候補作成（R2予定）

1. 元ファイルを読み取り専用で開き、チャンクCRC・順序・サポート可否を検査。
2. **IDAT内のzlibストリームだけ**をよりよい可逆方式で再圧縮。PNGフィルタ後の生データと全非IDATチャンクは必ず保持。APNG、未知の必須チャンク、パース不能は対象外。
3. 別の一時ファイルへ保存し、書き込み完了後に原本と候補を独立に読み直し検証。前後のzlib伸長バイト列が完全一致し、非IDATチャンクが完全一致し、全CRC正当性を確認。
4. 候補が十分小さく、対象ドライブに原本を保全できる作業余裕がある場合のみ、明示的に置き換え。電源断時の復旧ジャーナル設計を先に実装。
5. 容量不足・画質同一性証明不能・処理失敗は**変更せずスキップ**。

**注意**: PNGのテキストメタデータや不明な補助チャンクを黙って削除しない。アニメーションPNGは当面未対応。

## JPEGの候補作成（R2予定）

- 量子化されたDCT係数を変更しないエントロピー最適化など、画素を変えない手段のみ検討。
- JPEGのEXIF/ICC/XMP/コメント等をバイト一致で保持する検証がない限り適用しない。
- ファイルサイズが増えるなら無変更でスキップ。

## MP4について

- 動画・音声を再エンコードしない。コンテナを変えても画質は変わらないがメタデータやタイムスタンプが変化しうるため、R1/R2では重複統合のみを優先。
