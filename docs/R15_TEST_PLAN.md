# R1.5 — 実機試験とPNG無劣化候補の判定仕様

## 安全性の現在地

このキットはソース試験版。開発環境ではWindows/.NET 10 SDKがなく、C#ビルド・Windows NTFS実行テストを行っていない。
**通常のEXEからのハードリンク統合はビルド段階で無効化**してある。テストアセンブリ（CHAPPY_TESTING）の隔離フォルダ内でのみ統合を実行する。

## PNG候補生成の動作

1. 入力PNGを読み取り専用で開き、他プロセスの通常の書き込み・削除を排他する。
2. PNGの全チャンクを構造とCRCで検査。APNG・未知の必須チャンク・未知のunsafe-to-copy付加チャンクは除外。
3. PNGのIDATのzlibを展開。画像の寸法・色形式・インターレースから算出した展開後バイト数に厳密一致することを要求。
4. 展開後のフィルタ済みスキャンラインをそのままzlib再圧縮して、一時候補PNGのIDATだけを書き換える。
5. IDAT以外のチャンクは、画像内のEXIF・ICC・テキスト等も含めて**バイト列を変えずにコピー**。
6. 候補の全チャンクをCRCチェックし、IDAT以外のチャンク全バイトと、元/候補のIDATを展開した全バイトが一致することを確認。
7. 候補が厳密に小さかった場合だけ別名で残す。改善しなければ候補は削除。**元のPNGは一切変更しない。**

注意: ファイルシステムの作成日時・アクセス権・ADS等は候補に引き継がない。比較するのはPNG内部チャンクと展開後スキャンライン。R1.5には原本への上書き機能はない。

### R1.5制限

- 入力の生スキャンラインが512 MiBを超えるものはスキップ。
- 一時的に候補保存先へ「元ファイルサイズ + 8 MiB」の空き容量を要求。
- 圧縮率の改善は保証できない。PNGがすでに効率よく圧縮されている場合、候補は残らない。
- JPGやMP4の無劣化最適化は未実装。
- 統合後の独立化、一括復旧、PNG原本置換は未実装。
- 稼働中の重要ファイル、本番写真・動画には現時点では適用しない。

## Windowsでの試験手順

1. .NET 10 SDKを導入。
2. `RUN_TESTS.bat` を実行し、隔離されたテストフォルダで全テストがPASSすることを確認。
3. `BUILD_EXE.bat` を実行して、テストに合格した場合のみEXEを作成。
4. 作成したEXEではまず重複スキャン・PNG読み取り診断のみを試す。
5. 次に**別途コピーした検証用PNG**を選び、PNG候補を別フォルダへ作成する。元のPNGのSHA-256が不変、候補の見た目・メタデータが一致することを確認。
6. 少ない空き容量、壊れたPNG、APNG、インターレースPNG、巨大PNG、任意のメタデータ、強制中断で追加試験。
7. NTFSハードリンク統合の本番有効化は、復旧の障害注入や別プロセス競合も含む**Windows実機検証が成功した後に限る**。

## 検査用コード

`tests/Program.cs` に、非効率な正しいPNGを生成して候補縮小・原本SHA-256不変・テキストメタデータ保持・CRC破損拒否・改善しないPNGの候補破棄を試験するケースを追加した。Windowsで**まだ実行していない**。
