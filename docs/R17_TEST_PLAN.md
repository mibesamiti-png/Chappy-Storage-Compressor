# R1.7 テスト計画と安全条件

## 今回の追加機能

- `PngBatchJournalTools`: R1.6のJSONLを読み取って診断し、末尾の不完全JSONだけを明示的な同意後に修復する。元ログを `.before-r17-*.bak` に完全保存。
- 正常JSONの最後に LF がない場合は LF だけを追加。不完全な最後の1行は記録から除外するが、**バックアップには必ず残す**。途中行の不正/計画不一致/想定外の状態は修復を拒否。
- `ReadAudit` / `ExportCsv`: PNG候補を一覧化。源ファイルのサイズ・更新日時、および候補ファイルのサイズ・SHA-256を再確認。**源ファイルの全バイトは再照合していない**ため、削減見込みに実行保証はない。
- `JpegInspector`: JPEGのSOI/SOF/SOSヘッダ、EXIF・ICC・XMP識別子を読み取り専用で検査。映像の全画素復号や最適化は一切行わない。

## Windows自動テスト（未実行）

`RUN_TESTS.bat` または `dotnet run -c Release --project tests/ChappyStorageCompressor.SmokeTests.csproj`

1. 正常JSONL -> Healthy。参照レポート・CSVが取得できる。
2. 最後の行が切れている -> PartialTail。自動復帰はしない。明示修復で元ログ全体のバックアップ、断片のみ除去、既存キューを再開できる。
3. 完全な最終JSONなのに末尾LFなし -> MissingNewline。LFのみ追記。
4. 中間行が壊れている -> 安全停止。ログ自体は保持。
5. 原本ルート内へのCSV出力を拒否。
6. 修復前後で原本のSHA-256が一致。
7. JPEG合成ヘッダのサイズ/EXIFを解析し、破損ヘッダを拒否。

## 既知の制限

- ログは128MiB以下のみ修復対象。低空き容量では、元ログのバックアップと新しいログの両方を作れず失敗する可能性あり。
- バックアップログ、途中で生成された未参照プレビューは自動削除しない。
- プレビューの削減見込は実容量回復ではない。
- JPG/MP4の最適化と、候補による原本置換は未実装。
- この環境は.NET SDK・Windowsの実行環境を持たないため、C#のコンパイルやGUI動作は確認できていない。
