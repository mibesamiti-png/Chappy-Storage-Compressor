# R2.17 Part 27 — generated-only group manifest for 3+ aliases and restartable Undo between aliases

Part26 refused a completed-ledger merge of 3+ independent filenames because each Part24 record recorded a **fixed live master link count**; adding a second alias invalidated the first immutable completed record. Part27 adds a **separate group-level manifest** rather than weakening the individual record's link-count checks or modifying historical proofs.

## Concrete integration

- New `Core/CompletedGroupLedger.cs` contains a **production read-only inspector** and `CHAPPY_TESTING`-only `MergeSynthetic` / `ResumeUndoSynthetic`. Ordinary WPF and production Core do not gain any new user-file mutation API.
- At the start of the test-only group workflow, require an exact `ChappyStorageSmoke_` system TEMP NTFS sentinel, 3–33 previously independent media files, unchanged original identity/mtime/ctime/attributes/owner+DACL, exact bytes and SHA-256, and an empty pending recovery journal.
- Persist a disk-flushed, versioned `prepared` manifest **before** running the actual `DedupeEngine.Run`. It stores the group master path, representative original identity, and *every alias's* original NTFS identity, metadata and security descriptor. The old per-alias completed-ledger writer is deliberately **not** used on this group; it remains locked to supported two-file pairs. The existing actual Core transaction journal still protects each individual alias change.
- When all expected aliases share the exact master identity and there are no pending transactions, require master link count **2 + alias count** (representative + master store name + aliases), original SHA-256 and metadata, then finalize the group manifest. If any step fails or a partial merge occurs, leave the prepared record for **manual review** rather than declare success or automatically delete anything.
- Explicit group Undo reconstructs original snapshots from the *persisted* manifest, not a prior Scanner object, and invokes the real test-gated `IndependentUndoEngine.Restore` once per alias. Each successfully detached alias is verified against original bytes, times, attributes, owner+DACL, independent NTFS file ID and link count, then recorded as an **ordered durable checkpoint**.
- Before each subsequent Undo, the full manifest and checkpoint list are reverified. Expected master links are derived as **2 + originally merged aliases − durably detached aliases**. An unrecorded external link, swapped file, stale metadata, suspicious journal or malformed record prevents changes. An interrupted worker **between two completed alias checkpoints** is shown as `ExplicitResumeRequired` and only resumed on an explicit test-only request.

## Independent Windows test

`tests/R217GroupLedgerResumeTests.cs` creates **four independent same-content generated MP4 files** (representative + 3 aliases), runs the actual Scanner and DedupeEngine, verifies the group history, tests fail-closed refusal after adding a test-owned extra hardlink, and removes that exact generated alias only after identity/hash verification. A separately launched test runner performs actual Core independent Undo and then **kills its own worker process** right after the first group checkpoint has been flushed. The parent reopens history from disk, sees exactly one independent alias and an expected master link decrement, explicitly resumes the remaining two aliases, and checks all original SHA-256, NTFS IDs, ordinary attributes, timestamps, owner+DACL. A second Undo invocation must fail. CI has a strict machine-readable `diagnostics/r217-group-ledger-resume.json` gate.

## Explicit limits

This does **not** prove an arbitrary hard power cut, Windows/device-cache/NTFS directory durability, general concurrency or arbitrary ACL/SACL/ADS/EFS. The new worker is killed **between fully checkpointed aliases**, not within the internal `File.Replace` cutover or metadata restoration of a single alias. If a process dies mid-alias before its successful durable checkpoint, the group read-only inspector sees a mismatch and classifies it for **manual review**, not automatic replay. Multi-group/partial-group failures and cross-group operation ordering are still not a production transaction protocol. Existing Part25 tests cover internal process-kill windows only for their separately scoped single-alias completed ledger. We deliberately retain both proofs separately until a reviewed combined crash protocol exists.

All mutations in this part are synthetic-only and compiled behind `CHAPPY_TESTING`. Production hardlink consolidation, original JPG/PNG replacement and independent Undo remain disabled. End-user capacity reclaimed **0 B**, historical 69.4% source estimate unchanged and not release readiness. Require final PR-head Windows CI **and a separate postmerge main CI** before considering Part27 adopted.
