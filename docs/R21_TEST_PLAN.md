# R2.1 試験計画 — 重複と可逆圧縮の二重計上防止

## 実装した契約
- PNG/JPGの**検証済み候補**だけを取り込み、同じ元パスの見積もりは最大値を1回だけ計上。
- 既存の完全一致スキャン結果を再検証。各ファイルのサイズ・日時・属性・ファイル実体・SHA-256等が一致しなければ、その重複グループの理論削減量を除外。
- 同一データが2件ある場合、重複排除の理論節約量は1件分。候補再圧縮の節約量は共有データに対して最大1件分。
- これは**仮定上の論理容量**であって、ディスク使用領域の測定値でも、操作可能な処理計画でもない。
- 原本・候補・重複先を変更せず、実空き容量の回復量は0 B。

## Windowsで必ず実行する検証
1. .NET 10 SDK のあるWindows 10/11マシンで `RUN_DIAGNOSTICS.bat` を実行。
2. `diagnostics/RESULT.txt` が PASS であること、`build.log`、`smoke-tests.log`、`publish.log` にエラーがないこと。
3. テスト `TestR21NonOverlappingEstimate` の確認：重複計上の除去、スキャン後の変更拒否、パストラバーサル拒否、原本SHA-256維持。
4. NTFSテストボリュームで、読み取り専用スキャン → JPG/PNG候補の作成 → 統合容量レポート（スキャン結果を再利用）の表示を確認。
5. 重複ファイルの内容を1バイト変更し、同じ分析を再実行して誤計上が抑制されること。
6. 空き容量不足、読み取り権限拒否、途中での画像削除、既存ハードリンク、ReparsePointをそれぞれ確認。
7. 全ケースで画像原本のバイト列、階層、アクセス権が変化しないことを確かめる。

## この環境で実施したこと
- Python静的構成検証（**C#コンパイルの代わりにはならない**）。
- Python独立参考テスト（同じ仕様の別実装、**C#アプリ本体ではない**）。
- ZIP全メンバーのSHA-256照合。
