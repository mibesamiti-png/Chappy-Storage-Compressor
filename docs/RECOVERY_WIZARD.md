# R1.3 Recovery Wizard — 設計と操作ガイド

## 対象

ハードリンク統合の途中でアプリ停止、OS終了、I/O例外が発生した場合の退避ファイル・元パス・代表リンクを検査する。**本番利用前の試験機能**。

- `復旧ウィザード` → 読み取り専用の状態検査。SHA-256照合のためMP4が多いと時間がかかる。
- 一覧から対象1件を選択し、説明を読んで確認すると、明確に安全と判定された操作だけ実行可能。
- 記録に破損や不明な状態があれば、**何も消さずに手動確認**。新しい統合も禁止する。
- `復旧操作` は重複統合全体を元に戻す機能ではない。障害途中に残った**退避済みの独立コピー**を戻す処理である。

## 状態判定表

| 元パス | 退避ファイル | 照合結果 | ボタンで許可する操作 |
|---|---|---|---|
| あり | なし | 内容SHA-256一致 | **復旧記録の削除だけ**（ファイルは無変更） |
| なし | あり | 退避ファイルSHA-256一致、独立実体、ADSなし、正常属性 | **元パスへ移動**（上書きしない） |
| あり | あり | 元パス＝ストアのファイルID、退避ファイルは独立、両者SHA-256と全バイトが一致 | **元パスの共有リンクのみ解除して、独立した退避ファイルを元パスに戻す** |
| あり | あり | 上記の証明ができない | 手動確認、ファイル削除禁止 |
| なし | なし | 不明 | 手動確認、ファイル削除禁止 |
| 任意 | 任意 | ジャーナル壊れ／範囲外パス／reparse point／照合不一致／アクセス失敗 | 手動確認、ファイル削除禁止 |

## 保護ルール

1. すべての書き込み操作は、実行直前に現在のファイル状態を**再判定**する。
2. 検査に利用するファイルは、再判定・復旧の間、他プロセスからの書き込みを拒否できる共有モードで開く。操作に必要な共有アクセスが得られない場合は停止。
3. `元パス` の削除が必要な場合も、**ストアのファイルIDと完全一致するハードリンク**と確認した1パスだけを解除する。ストアの代表ファイルや退避データは削除しない。
4. `File.Delete(元パス)` の直後に `File.Move(退避, 元パス)` が失敗しても、退避ファイルは残り、ジャーナルも残る。再検査後に復元可能。
5. 旧形式の記録も読む。R1.3からは独立ファイル・ストアのファイルIDを追加で保存し、記録がある場合には照合する。
6. 破損したジャーナルが存在するときは、復旧処理自体も中断する。
7. 明示確認は1件ずつ。自動一括復旧は実装しない。

## 未解決・次の検証

- **Windows実機**で5地点の模擬強制終了テストを実行し、ファイル共有・リネーム・ハードリンクのOS挙動を確認する。
- ファイルシステムの多プロセス同時変更、外部同期、ACL変化、ボリューム障害は未検証。
- R1.3の復旧は、全データの独立性を自動で復元する「統合解除」機能ではない。統合処理が完了し退避コピーを削除した後は、独立コピーを増やすために**追加の空き容量**が必要。
- 重要データを対象にしない。別ドライブのバックアップを必須とする。

## 復旧処理自体の中断テスト

R1.3ではテスト専用チェックポイント `recovery-link-removed` を追加。共有リンクの削除直後に模擬強制終了し、独立退避ファイルと復旧記録が残り、次回の検査で「元パスがなく退避だけ存在」へ分類が変わるかを確認するテストを用意した（**Windows実行未確認**）。
